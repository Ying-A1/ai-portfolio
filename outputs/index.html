01

AI / AGENT / BOUNDARY

我对 AI 的理解

模型提供理解，Agent 推动行动，系统守住边界。

AI 的价值不只在一次回答。它开始理解目标与上下文，并通过 Agent 进入连续任务。Harness 决定这套能力如何获得上下文、调用工具、保存状态、接受授权并验证结果。

01 / UNDERSTANDING

AI 理解目标

模型在上下文中识别意图、约束与歧义，形成解释和推理；它提供认知能力，但一次生成并不等于任务已经完成。

目标 · 上下文 · 推理
02 / ACTION

Agent 推进任务

Agent 把理解放进感知、规划、行动与反馈的闭环，通过工具和环境推进任务，并依据结果更新下一步。

感知 → 规划 → 行动 → 反馈
03 / BOUNDARY

诚实面对边界

系统需要知道何时请求证据、授权或人工接管，并把已确认、未确认与未覆盖分开表达。诚实来自可追溯的能力与证据边界。

证据 · 权限 · 接管
02

AI TO BUSINESS

我的判断 · AI TO B

从能力演示，
走到业务系统。

企业场景首先要回答五件事：私有数据怎么进入上下文，谁能使用哪些能力，系统部署在哪里，效果如何持续评估，以及上线后的故障、成本与版本如何运营。

我会明确区分 PoC 可运行、业务可用、正式上线、规模化复制。每个阶段需要不同的证据，不能用一次成功调用代替交付结论。

DATA

数据与上下文

来源、质量、时效、隔离方式，以及能否安全进入模型上下文。

CONTROL

权限与部署

身份、授权、审批、环境边界和敏感动作的责任归属。

EVAL

评测与边界

任务指标、Badcase、人工验收，以及已确认、未确认和未覆盖。

OPS

运行与迭代

日志、成本、稳定性、恢复、版本管理和持续反馈。

应用到项目 / 01Android Personal Agent

把权限、构建结果与真机端到端边界分开记录；完成构建不等于设备行为已经通过。

应用到项目 / 02Slide Studio

把“可继续编辑”和“可以导出”作为生成物进入真实工作流的必要条件。
